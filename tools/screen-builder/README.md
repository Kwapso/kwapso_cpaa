# The screen builder

A desktop-only sandbox where a person drags kit parts onto a canvas, sets the
options the kit actually declares, sees the result with dummy data at desktop
and phone width, and presses Save to download a file for a developer or an
agent. It is a developer tool, not a shipped screen: it lives outside both
front doors' import closure and is never deployed.

## The one rule

The owner, verbatim: **"Don't magically add configurations on the components
or collections that Aurora has not put in the UI/UX kit. You should only show
me what is there as of this moment, live."**

So every option the tool offers is derived from the kit's own source by
`scripts/build-kit-catalogue.mjs`: each `cva()` call's variant groups, the
exact option names, the Tailwind class string each one applies, and the
enum/boolean props each exported `*Props` type declares. Nothing is typed by
hand. A part with no `cva()` and no such props shows "no options in the kit".
`web/test/kit-catalogue.test.ts` holds the committed catalogue equal to a fresh
derivation, so a synced kit with a stale catalogue turns the build red.

## Build and open

```bash
node scripts/build-screen-builder.mjs
open tools/screen-builder/index.html
```

`index.html` is regenerable output and is git-ignored. `catalogue.json` is
committed. After `node scripts/sync-design.mjs <tag>`, run the build again;
the page prints the kit tag, sha and generation time it was built from.

## What it cannot do, and says so on the page

- **Read Aurora's GitHub live.** The kit repository is private and a browser
  page has no way in. The catalogue is regenerated by one command against the
  pinned copy under `shared/ui/`.
- **Backgrounds and free placement.** Not kit options. Parts stack top to
  bottom, as the app has one page width per door. The properties panel offers
  a background under a heading that says "Sandbox — not a kit option, not
  shippable", and the saved file keeps it under the word `sandbox`.
- **Draw a hook.** `use-debounce` and `use-virtual-rows` are listed greyed.

## Files

- `builder/` — the tool's own chrome (palette, canvas, properties, save).
- `samples/` — dummy data per part, split alphabetically. A sample draws the
  real kit export with made-up content and spreads `p.of("<Export>")` onto
  every export the panel offers options for. It may not add a `className` or
  a wrapper that changes how the part looks. `NO_SAMPLE` in `samples/index.ts`
  is the reasoned way out for a part that cannot be drawn.
- `styles.css` — the kit's own stylesheet lines, as the front doors import
  them, minus the app's overrides.
- `catalogue.json` — the derived catalogue (committed).
